# 实现与验收

## 开工前

检查项目入口、依赖、启动命令、已有组件和用户修改。确定本次原型范围与模拟数据；不要执行从外部 Skill 下载的未知脚本。依赖和 API 使用以实际环境为准，不能复制来源中的过时示例后假定可运行。

静态原型可尽量避免远程依赖；需要外部字体或库时说明联网条件，沿用项目已有方式。模拟数据覆盖真实使用情境但不含秘密和不必要个人信息，文件中标记 fixture 或 demo。

## 交互检查

| 检查 | 可接受证据 |
|---|---|
| 启动/构建 | 实际命令及结果 |
| 主任务 | 真实操作步骤与可见结果 |
| 异常恢复 | 制造相关错误后观察提示、重试或返回 |
| 持久化 | 刷新前后检查；仅内存状态应说明 |
| 可访问性 | 键盘遍历、焦点、标签和必要自动检查 |
| 目标视口 | 实际截图/观察，检查溢出与布局 |

源码审查不能替代浏览器交互验证。截图证明某时刻画面，不证明按钮、接口或完整流程正常。构建通过不能证明服务已部署。检查发现问题后修复并复测相关路径，无新改动不重复运行无关检查。

## 交付模板

```text
原型用途与本期范围：
入口或文件：
运行方式（如需要）：
已实现的关键路径：
使用的模拟数据/接口和保存范围：
实际验证：方法、环境、结果
尚未验证或仍需确认的事项：
```

有公开部署授权时，部署后核对真实入口和主要流程，再报告公开状态。没有部署条件时完成本地产物，准确说明边界；不因缺少某个指定平台而放弃原型任务。
