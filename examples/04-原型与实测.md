# 回声：人工审核原型与实际检查

本次实际实现的范围是“查看原文 → 改分类 → 确认/撤销 → 导出”。输入为 8 条合成反馈，分类为预置建议；没有调用分类模型，也没有实现批次导入和后台持久化。

打开 [交互原型](../demo/prototype.html) 后，左侧选择反馈，右侧保留只读原文、AI 初始建议和人工选择。AI 原建议始终保留；人工修改不会覆盖原文，也不会被当作模型自己判断正确。

F007“ 不好用 ”没有足够信息，保持待判断，确认按钮不可用。F001 可以查看与 F003 的关联，但它们仍然是两条反馈。确认后才纳入 CSV；改动已确认的分类会撤销确认。

## 实际浏览器检查

| 操作 | 本次观察结果 |
|---|---|
| 初始打开 | 8 条记录、2 条待判断、0 条确认；导出不可用 |
| 键盘聚焦确认按钮并按 Enter | F001 变为已确认，计数为 1 |
| 再确认 F003 并下载 | 实际 CSV 回读为 F001、F003 两条 |
| 将已确认 F001 改为功能建议 | 确认计数降为 1 |
| 再次下载 | 实际 CSV 仅包含 F003 |
| 筛选待判断 | F007、F008 可见；F007 的确认按钮不可用 |

CSV 同时保存初始建议和人工最终分类；`suggestion_reason` 是原建议依据，不是人工判断理由。所有导出均为本地文件，不会向研发系统创建任务或发送消息。

刷新页面会恢复演示初始状态，界面已有说明。浏览器检查证明本地演示的这些交互可用，不代表完成真实用户测试、生产模型评测或后台开发。
